# Design System

## Overview

This project uses a **shadcn/ui** design system built on top of **Tailwind CSS** and **Radix UI** primitives. Components are organized following Feature-Sliced Design (FSD) conventions.

## FSD UI Organization Rules

```
src/
├── shared/ui/          # shadcn/ui primitives (Button, Card, Badge, etc.)
├── entities/*/ui/      # Domain-specific components (e.g. entities/job/ui/job-card.tsx)
├── features/*/ui/      # User actions and workflows (e.g. features/import-job/ui/import-job-dialog.tsx)
└── widgets/            # Page-level compositions
```

## Component Ownership

| Layer | What goes here | Example |
|-------|---------------|---------|
| `shared/ui` | shadcn/ui primitives only | Button, Card, Badge, Dialog, Input, Table |
| `entities/*/ui` | Domain components tied to a business entity | JobCard, CompanyProfile |
| `features/*/ui` | User actions and multi-step workflows | ImportJobDialog, SkillGapAnalysis |
| `widgets` | Page-level compositions that combine features and entities | JobSearchPage, Dashboard |

## Documented Primitives

| Primitive        | Doc                                        | When to use                                                              |
| ---------------- | ------------------------------------------ | ------------------------------------------------------------------------ |
| Drawer           | [`drawer.md`](./drawer.md)                 | Secondary workspaces: details, editors, monitors, filters, forms         |
| DebouncedInput   | [`input.md`](./input.md)                   | **All** text search / filter inputs (debounced to reduce server load)    |

## shadcn/ui Conventions

- All primitives in `shared/ui/` are generated by `npx shadcn@latest add`
- Components use `class-variance-authority` (cva) for variant management
- Tailwind classes are merged via `cn()` utility from `shared/lib/utils.ts`
- Radix UI primitives provide accessible behavior (dialog, dropdown, etc.)

## Storybook Usage

### Running Storybook

```bash
npm run storybook
```

Opens Storybook at `http://localhost:6006`.

### Building Storybook

```bash
npm run build-storybook
```

Output is written to `storybook-static/`.

### Writing Stories

Stories live alongside their components using the `.stories.tsx` convention:

```
src/shared/ui/button.tsx
src/shared/ui/button.stories.tsx
```

Place stories at the same FSD layer as the component they document.

### Storybook Configuration

- `apps/frontend/.storybook/main.ts` — Storybook config (stories pattern, addons, framework)
- `apps/frontend/.storybook/preview.tsx` — Global preview config (CSS import, controls, a11y)
