# Workflow Progress

## Purpose

This document describes how workflow execution progress is generated, stored, and delivered to clients.

Workflow progress provides visibility into long-running background executions.

Examples:

- Job processing progress
- Content extraction progress
- LLM analysis progress
- Scoring generation progress

The progress system separates:

- Workflow execution
- Execution state
- Progress events
- Client notifications

---

# Architecture Overview

Progress flow:

LangGraph Workflow

↓

Workflow Nodes

↓

Progress Events

↓

ProcessingExecution Events

↓

SSE Stream

↓

Frontend

---

# Progress Ownership

Workflow progress is generated by the workflow execution layer.

The workflow engine is responsible for reporting:

- Current node
- Node status
- Execution stage
- Intermediate results
- Completion state

TaskIQ is not responsible for progress management.

TaskIQ only executes the background task.

---

# Progress Model

A workflow execution produces progress events.

Examples:

- WorkflowStarted
- NodeStarted
- NodeCompleted
- WorkflowProgressUpdated
- WorkflowCompleted
- WorkflowFailed

Each event contains:

- Execution identifier
- Event type
- Timestamp
- Current workflow stage
- Additional metadata

---

# ProcessingExecution Integration

ProcessingExecution is the domain representation of an execution.

It stores:

- Execution status
- Execution metadata
- Progress information
- Failure information

Workflow progress updates modify the execution lifecycle.

Example:

ProcessingExecution

Created

↓

Queued

↓

Running

↓

Progress Updates

↓

Completed

or:

Running

↓

Failed

---

# LangGraph Integration

LangGraph is responsible for workflow state.

Progress is generated from workflow nodes.

Example:

Fetch URL Node

↓

Progress: Fetching content

Extract Content Node

↓

Progress: Extracting information

LLM Node

↓

Progress: Analyzing content

Scoring Node

↓

Progress: Generating score

---

# Event Delivery

The backend exposes progress updates through SSE.

Flow:

LangGraph

↓

Processing Event

↓

SSE Endpoint

↓

Frontend

The frontend should not poll workflow state continuously.

---

# Frontend Usage

Frontend uses progress events to display:

- Current step
- Execution status
- Loading state
- Completion state
- Error messages

Examples:

Processing...

Fetching website content

Analyzing information

Generating career score

Completed

---

# Failure Handling

Progress events must handle failures.

Failure event example:

WorkflowFailed

Contains:

- Execution identifier
- Failed stage
- Error information
- Timestamp

The frontend uses this event to display failure state.

---

# Persistence

Progress information can be persisted through:

- ProcessingExecution records
- Event storage
- LangGraph checkpoints

The source of truth depends on the type of information:

Execution lifecycle:

PostgreSQL

Workflow state:

LangGraph checkpoint

Temporary delivery:

SSE
