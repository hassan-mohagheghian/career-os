# Redesign Add Job Tab — Clear Processing Workflow

## Problem
The "Add Job" tab has an unclear process workflow:
1. The "How it works" section is a wall of text that's hard to scan
2. The process button is tiny (h-6) and not prominent
3. Process button shows on both `queued` AND `processing` — but `processing` should be disabled
4. Failed jobs have no "Retry" button
5. Step 3 says "Tell me process" which is confusing UI copy

## Solution — Visual Pipeline Flow + State-Aware Button

### File: `app/client/src/App.jsx`

### Changes

#### 1. Replace "How it works" text block with visual pipeline flow
Replace the 5-step text guide with a horizontal visual pipeline:
```
[📋 Add URL] → [⏳ Queued] → [🚀 Process] → [🌐🔍📄💾✅ Pipeline] → [✅ Done]
```
- Each step is a compact icon+label chip
- Active step highlighted with accent color
- Compact, scannable, visual — no paragraph text

#### 2. State-aware process button in PendingItem
Current behavior:
- `queued` OR `processing` → Process button shown
- `done` or `failed` → No process button

New behavior:
| Status | Button | Style |
|--------|--------|-------|
| `queued` | **Process** | Green gradient, prominent |
| `processing`/`fetching`/`analyzing`/`resumed`/`saving` | **Processing...** (disabled) | Accent color, spinner icon |
| `done` | No button | — |
| `failed` | **Retry** | Orange gradient, retry icon |

The button is always passed to `PendingItem`; the component decides what to render based on status.

#### 3. PendingItem button rendering update
- Pass `onProcess` for ALL non-done items (remove the `queued||processing` filter from parent)
- Inside `PendingItem`, derive button state from `statusKey`:
  - `queued` → green "Process" button (enabled)
  - `fetching`/`analyzing`/`resumed`/`saving` → accent "Processing..." button (disabled, spinner)
  - `failed` → orange "Retry" button (enabled, calls same `onProcess`)
  - `done` → no button

#### 4. Compact the visual design
- Reduce padding, font sizes for the guide section
- Make the step pipeline in PendingItem tighter
- Remove redundant "How it works" source/status text explanation (it's self-explanatory from the UI)

### What stays the same
- All backend API endpoints (no changes)
- SSE stream for real-time updates
- Filter tabs (Active | Completed | Failed | All)
- Step pipeline circles in PendingItem (just minor spacing tweaks)
- Error display in PendingItem

## Verification
1. Run `cd app/client && npm run dev` and open the Add Job tab
2. Paste a LinkedIn URL → should appear as "queued" with green "Process" button
3. Click Process → button changes to disabled "Processing..." with spinner
4. Steps animate through the pipeline
5. On completion → "Completed" tab, no button
6. On failure → "Failed" tab, orange "Retry" button
7. Click Retry → re-triggers the pipeline
