# Prompt 158 - Company context reads notes+links from company_links; drop redundant companies.notes

## Objective

Make company context preparation succeed when a company's links yield no
content but it has notes, and remove the redundant company notes storage.

Concrete case: company `01a003cf-58c0-772d-8286-aacf2ba01736` (A2G) has a text
note and a link added via the UI — both stored in `company_links` — yet its
processing failed with `no extracted content; empty notes` because the context
preparation only read the (empty) `companies.notes`/`links` JSON columns.

## Root Cause

- Notes/links added via `POST /companies/{id}/notes` and `/links` are stored in
  `company_links` (notes = `note:`-prefixed rows, links = URL rows) — the
  canonical, separate store.
- But `CompanyService.get_company` returned only the `companies` row via
  `get_by_id`, which never surfaced `company_links`; `CompanyData.links_raw` /
  `notes_raw` defaulted to `[]`, so `collect_sources` saw nothing.
- `companies.notes` was a **redundant** column: only `create_from_intake`
  (POST /companies) wrote combined notes+links into it; the UI note/link CRUD
  uses `company_links`.

## Changes

- `companies/application/services/company_service.py`:
  - Add optional `link_repository` to `CompanyService.__init__`.
  - `get_company` merges `company_links` into the returned dict as `notes`
    (text notes) and `links` (URL links) JSON arrays when a link repository is
    present.
  - `create_from_intake` writes notes and links into `company_links` instead of
    the removed `companies.notes` column.
- `companies/infrastructure/models/company_model.py`: remove the redundant
  `notes` and `links` columns (canonical storage is `company_links`).
- `companies/infrastructure/repositories/sa_company_repository.py`: drop
  `notes` from `update()`'s writable field list.
- `companies/presentation/api/companies_v2_router.py`: inject link repo into the
  create endpoint's `CompanyService`; drop `notes` from the create response.
- `companies/presentation/api/schemas/companies_v2.py`: remove `notes` from
  `CompanyCreateResponse`.
- `processing/application/services/processing_queue_service.py`: `_company_links`
  now reads `links` (new shape) instead of `notes`.
- `processing/infrastructure/workflow/assembly.py`: pass
  `SQLAlchemyCompanyLinkRepository` into every `CompanyService`.
- Migration `apps/alembic/company/versions/6806b605992a_drop_companies_notes_column.py`
  (autogenerated, tuned) drops `company.companies.notes`.
