# Prompt 183 - Feature: Application Notes (free-text activity log on the Application Workspace)

## Objective

Let the user attach **notes to a job's application** — simple free text in
their own words, each stamped with its creation time — so their activities
around an application (calls, emails, interviews, decisions) are traceable.
Notes are listed **newest first** and each can be deleted. They live in the
Application Workspace (`/jobs/{job_id}/application`) as a new **Notes**
section, next to Tracker / Roadmap / Documents.

## Current State

- The Applications bounded context (`apps/backend/applications/`) owns the
  `application` schema: `applications`, `application_status_timeline`,
  `application_follow_ups`, `application_documents`
  (`infrastructure/models/application_model.py`).
- `FollowUpService` + `SQLAlchemyFollowUpRepository` are the closest analog:
  port interface, SA repo with `list_for_application`, service emitting domain
  events best-effort via `InMemoryEventCollector`, router sub-resource
  `POST /{id}/follow-ups` / `DELETE /follow-ups/{id}`, providers in
  `dependencies.py`.
- `ApplicationDetailResponse.build_detail_response` embeds children
  (timeline, follow_ups, documents); frontend mirrors this in
  `entities/application/{types,api,hooks}.ts` and renders sections in
  `features/job-application/components/ApplicationWorkspace.tsx`.
- Latest application migration head: `application_005`
  (`apps/alembic/application/versions/`). Migrations are autogenerated first,
  then tuned (rule 14). FKs only within the `application` schema (rule 15).

## Implementation Steps

1. **Model** `ApplicationNoteModel`: table `application_notes`, schema
   `application`; columns `id` (uuid7 str36 pk), `application_id` (FK →
   `application.applications.id`, indexed), `content` (Text), `created_at`,
   `updated_at` (ISO strings via `_now_iso`).
2. **Mappers**: `note_model_to_dict` / `dict_to_note_model` in
   `infrastructure/mappers.py`.
3. **Repository**: port `INoteRepository`
   (`domain/repositories/note_repository.py`: create, list_for_application,
   get_by_id, delete) + `SQLAlchemyNoteRepository` — list ordered
   `created_at DESC` (rule 7: newest first).
4. **Domain events** (rule 16): `ApplicationNoteAdded`
   (`application.note.added`) and `ApplicationNoteDeleted`
   (`application.note.deleted`), emitted by `NoteService` best-effort;
   catalog entries in `docs/domain/applications/events.md`.
5. **Service** `NoteService` (`application/services/note_service.py`):
   `add(application_id, content)` (validates non-empty content after trim,
   404 when application missing) and `delete(note_id)` (404 when missing),
   mirroring `FollowUpService`.
6. **Schemas**: `CreateNoteRequest(content)` (strip + non-empty validator),
   `ApplicationNoteSchema`; add `notes: list[ApplicationNoteSchema]` to
   `ApplicationDetailResponse` + `build_detail_response`.
7. **Router** (`applications_router.py`): `POST
   /{application_id}/notes` → 201 + note; `DELETE /notes/{note_id}` → 204.
   Include notes in all detail responses (`_detail`, by-job, create, update).
8. **Providers**: `get_note_repo`, `get_note_service` in
   `dependencies.py`; lazy exports in `applications/infrastructure/__init__.py`.
9. **Migration**: `uv run alembic revision --autogenerate -m "add application
   notes"` → tune content (naming as in `application_004`) → rename to
   `application_006_add_notes.py` → verify history/heads single-head +
   upgrade/downgrade round-trip.
10. **Frontend entity**: `ApplicationNote` type + `notes` on
    `ApplicationDetail` + `CreateNoteInput`; `applicationApi.addNote /
    deleteNote`; `useAddNoteMutation` / `useDeleteNoteMutation`
    (invalidate `[APPLICATION_KEY]`).
11. **Frontend UI** `features/job-application/components/ApplicationNotes.tsx`:
    textarea + Add button (disabled while empty/pending), list of notes newest
    first showing relative/absolute creation time (`DateTime`) and a delete
    button per note (rule 9); empty state text; wired into
    `ApplicationWorkspace` as a new "Notes" section after Documents.

## Testing

- Backend: extend `tests/applications/presentation/api/test_applications_router.py`
  with `TestNoteAPI` (add + appears in detail, delete removes row, 404s,
  empty-content 422, newest-first ordering).
- Frontend: `ApplicationNotes.test.tsx` (renders notes newest first with
  timestamps, add calls api + clears input, empty input disabled, delete calls
  api, empty state).
- Run `uv run pytest apps/backend/tests/applications -v`, `npx vitest run`
  (targeted files), `npm run typecheck`.

## Constraints

- Notes are plain text + created_at only — no edit endpoint, no titles.
- Newest-first ordering everywhere (rule 7); hard delete (rule 8 analog);
  delete button per note card (rule 9).
- FK within the `application` schema only (rule 15); ORM only (rule 2);
  structlog/no print; events documented even though pub/sub is deferred
  (rule 16).
- Docs: `docs/ux/features/applications/application-notes.md` (ASCII wireframe +
  Mermaid), update `workspace.md`, `docs/ux/README.md`, events catalog; this
  prompt. One prompt = one commit (with this file).
