# Prompt 091 - Skill Mentions, Company Skill Extraction, Aliases + Merge UI

## Objective

1. **Skill mentions (demand signal)** — count how often each skill appears in
   processed jobs and company analyses. Add a `skill_mentions` table, persist
   mentions during job processing and company analysis, expose a per-skill
   mention count in the list API, and render a sortable Mentions column.
2. **Company skill extraction** — company analysis now returns an
   `extraction.skills` array (validated, scored, persisted into
   `skill_mentions` with `source_type="company"`), matching the job pipeline.
3. **Alias + merge UX** — add alias add/remove endpoints and UI in the Edit
   drawer, plus a Merge Skill dialog. Merging folds mentions into the target and
   turns the source into a hidden alias.

## Current State

- `SkillModel` has `source`/`source_type` (`user_input`/`ai_generated`) and an
  `aliases` JSON column. No mention table exists. No `/skills/{id}/aliases` or
  `/skills/merge` routes.
- Job analysis already persists extracted skills via `PersistSkillsNode`; company
  analysis does not extract skills at all (prompt/schema v1.1.0).
- Frontend skills list has no Mentions column; Edit drawer has no alias or merge
  UI.

## Implementation Steps

1. **Migration (rule 14)** — add `SkillMentionModel` (`id`, `skill_id` FK →
   `skill.skills` ondelete CASCADE, `source_type`, `source_id`, `status`,
   `evidence`, `created_at`, unique `(skill_id, source_type, source_id)`, index
   on `skill_id`). Generate with `uv run alembic revision --autogenerate -m
   "add_skill_mentions_table"`, review/tune, apply. NOTE: `skill_001` is a stale
   branchpoint; the tuned migration sets `down_revision="company_006_normalize_intelligence_score_keys"`
   and lives in `apps/alembic/skill/versions/`.
2. **Mentions repository** — `resolve_skill` (get-or-create by name),
   `upsert_mentions` (unique-key on conflict do nothing), `delete_mentions_for_source`,
   `get_mention_counts` (group by skill, include 0-count skills).
3. **Job pipeline** — `PersistSkillsNode` (`SOURCE_TYPE="job"`) upserts mentions
   after persisting skills; wiring order is
   `persist → persist_skills → analysis_ready`.
4. **Company pipeline** — add `extraction.skills` to validation
   (`_coerce_skill_list`, name/reason/relevant/skills), scoring (skill scores),
   prompt schema v1.2.0 + `company_combined_analyze.txt` template (10-skill cap).
   New `PersistCompanySkillsNode` (`SOURCE_TYPE="company"`, no-ops when
   `skill_repo is None`), wired into `CompanyAnalysisGraph` with a new
   `skill_repo` param after `NODE_PERSIST_COMPANY_SKILLS`.
5. **List API** — `mention_count` on `SkillListItemSchema`; `list_skills_v2`
   attaches counts to all filtered rows before sorting;
   `SORTABLE_SKILL_FIELDS` includes `mention_count`.
6. **Aliases + merge** — `add_alias`/`remove_alias` in repo interface + SA impl;
   routes `POST /skills/{id}/aliases` + `DELETE /skills/{id}/aliases/{alias_name}`;
   schemas `SkillAliasAdd`/`SkillAliasRemove`; merge folds mentions via
   `_fold_mentions` (skip duplicate `(source_type, source_id)` keys), adds source
   name as target alias, hides source; `delete` also deletes mention rows.
7. **Frontend** — `mention_count` in types; Mentions column
   (`SKILL_GRID_TEMPLATE`, `skillsColumns.ts`, `SkillRow`) activating
   `SortableHeader`; alias add/remove UI + merge button in `SkillEditDrawer`;
   new `MergeSkillDialog` (search candidates excluding current, `GitMerge` icon —
   `Merge` does not exist in `@phosphor-icons/react`); API methods
   `addAlias`/`removeAlias`/`merge`; sort field type += `mention_count`.
8. **Docs** — api-design skills table, `docs/api/skills/get-skill.md`,
   `docs/api/skills/merge-skills.md`, list-skills sort/response fields,
   UX: page/skill-row/skill-detail/edit-skill, new
   `docs/ux/flows/skills/merge-skills.md`, UX README index.

## Testing Requirements

- Backend: `test_skill_mentions.py` (upsert/unique/count/delete, persist nodes,
  mention_count in list, sort by mention_count), alias add/remove + merge fold
  tests, company `extraction.skills` validation/coercion tests.
- Frontend: `MergeSkillDialog.test.tsx`, `SkillEditDrawer` alias/merge tests,
  `SkillRow` mention rendering; typecheck clean for changed files.
- Full suites: `uv run pytest apps/backend/tests/ -v`,
  `cd apps/frontend && npx vitest run`, `npm run typecheck`.

## Constraints

- No routes in `entrypoints/api.py`. SQLAlchemy ORM only. No `print()`.
- Migrations autogenerated + tuned (rule 14), single Alembic head, applied to dev
  DB.
- Company prompt/schema version bump 1.1.0 → 1.2.0 (keep all version references
  in sync).
- Rule 13: every UI change ships with wireframe/flow docs updated.
