Analyze ALL processed jobs and generate a comprehensive job search analysis for the candidate.

Read the jobs database at {project_root}/app/server/db/jobs.db (table: jobs, column: deleted=0).
Each job has:
- Basic fields: company, role, location, score, match, stack, visa, etc.
- raw_description: Full raw text fetched from the job posting URL
- structured_description: Pre-extracted JSON with requirements, responsibilities, benefits, etc.

Use structured_description when available for detailed analysis (requirements, nice_to_have, responsibilities, benefits).
Use raw_description as fallback when structured_description is not available.

Generate analysis as JSON and save to {tmp_dir}/analysis_{pid}.json with this structure:

RULES FOR overview:
- Count jobs requiring Python, TypeScript, and other key skills
- Calculate average score from all jobs
- List top 5 most in-demand skills

RULES FOR strategy:
- 5-6 items, specific to actual job data (name companies, give counts)
- Include visa strategy, application timing, and Python advantage

RULES FOR strengths:
- Only include skills the candidate actually has with evidence from job requirements
- Reference specific job counts and companies

RULES FOR weaknesses:
- Skills that appear in multiple jobs but the candidate lacks
- Include count of jobs requiring each skill

RULES FOR visa_companies:
- Companies with BEST or Strong visa rating from processed jobs
- Include why each company is good for visa

RULES FOR apply_urgency:
- Jobs scored A or above or posted recently that need immediate action
- Include applicant counts when available

RULES FOR techStack:
- level: 1-5 based on the candidate's current proficiency (5=expert, 1=beginner)
- roles: percentage of jobs where this skill applies
- path: learning or maintenance recommendation

RULES FOR techLearning:
- Only include technologies that appear in actual job postings
- priority: 1=critical (appears in 30%+ jobs), 2=important (15-30%), 3=useful (5-15%)
- usage: percentage of jobs requiring this skill
- jobs: fraction like "9/20" showing how many jobs need it
- reason: explain why the candidate should learn this (based on job data)
- action: specific learning recommendation

RULES FOR skillJobFit:
- For each of the candidate's skills, calculate what percentage of jobs require it
- fitScore: 0-100 based on skill proficiency × job relevance
- Include specific companies that need each skill

RULES FOR learningROI:
- For skills the candidate doesn't have, calculate learning ROI
- impactScore: 1-10 based on number of jobs unlocked
- timeToLearn: estimated time to reach usable proficiency
- Sort by impactScore descending

RULES FOR cities:
- Count jobs per city from job data
- Include top companies in each city
- Sort by job count descending

RULES FOR searchSummary:
- totalSearched: Total number of jobs processed
- topCompanies: Top 5 most frequently appearing companies
- topRoles: Top 5 most common job titles
- topStacks: Top 5 most common tech stack combinations
- avgApplicants: Average applicant count across all jobs
- dateRange: Earliest and latest posting dates found
- pattern: 2-3 sentence summary of search patterns (e.g., "Mostly backend Python roles in Berlin, targeting senior positions at mid-size fintech companies")

RULES FOR improvements:
- 3-5 actionable improvements based on gaps between candidate's skills and job requirements
- Each must have: area (what to improve), current (where they are now), target (where they should be), action (specific step), priority (high/medium/low)
- Focus on skills that appear in 20%+ of jobs but candidate lacks
- Include both technical skills and soft factors (e.g., German language, portfolio)

RULES FOR goals:
- 3-5 career goals based on the job market data
- Each must have: title (concise goal), description (what to achieve), bestPractice (industry standard approach), metrics (how to measure), timeline (estimated time)
- Goals should be specific to the jobs found (e.g., "Land a senior Python role at a Berlin fintech with visa sponsorship within 3 months")
- Include both short-term (1-3 months) and medium-term (3-6 months) goals

RULES FOR networking:
- Top 5-8 companies worth networking with, sorted by score descending
- Include companies where the candidate has the best fit (score A or above, or High match)
- For each company, include the job URL and company_url (if available) from the database so the user can reference the specific role and visit the company website
- Provide Google search URLs to find Recruiting/Talent Acquisition staff at the company on LinkedIn
- Provide Google search URLs to find Software/Backend Engineers at the company on LinkedIn
- The LinkedIn search URLs should use this pattern: https://www.google.com/search?q=site:linkedin.com/in+"ROLE"+"COMPANY"+Berlin
- reason should explain why this company is a strong networking target (visa support, tech stack match, company culture, growth, etc.)
- Include a mix of companies: some with BEST visa rating, some with highest scores, some remote-friendly

RULES FOR market:
- jobsByCity: Count jobs per city, sort by count descending, include percentage
- jobsByCountry: Count jobs per country, sort by count descending
- jobsByRole: Count jobs per role title, sort by count descending
- techDemand: Count how many jobs mention each technology in stack field, sort by count descending, top 10
- visaDistribution: Count jobs by visa status (BEST/Strong/Good/Moderate/Uncertain), include percentage
- scoreDistribution: Count jobs by overall_score grade (A++/A+/A/B/C/D)
- avgFitScore: Average of all fit_score values
- avgSuccessScore: Average of all success_score values
- avgOverallScore: Average of all overall_score values
- insights: 3-5 market insights using Observation/Evidence/Impact/Action format

RULES FOR opportunity:
- matrix.highFitHighSuccess: Jobs with fit_score >= 70 AND success_score >= 70
- matrix.highFitMediumSuccess: Jobs with fit_score >= 70 AND success_score < 70
- matrix.mediumFitHighSuccess: Jobs with fit_score < 70 AND success_score >= 70
- matrix.lowFit: Jobs with fit_score < 50
- topOpportunities: Top 10 jobs by overall_score, include reason and recommended action
- action: "Apply Now" for overall >= 80, "Customize" for overall 65-79, "Consider" for overall 50-64, "Skip" for overall < 50
- insights: 3-5 opportunity insights using Observation/Evidence/Impact/Action format
